# InfraSpace Multi-Resource Logistics

让配送中心和搜集中心同时处理多种物资。

## 功能

- 顶部直接排列所有已选物资图标，末尾的 `+` 用于添加物资。图标会标红：该物资没有配对的搜集中心或配送中心，或者配对中心之间没有货车路径。鼠标放上图标可看到配对中心名称。左键把图标变成灰色，这件物资只保留库存，不再搜集、配送或转给配对中心；再点一次恢复。
- 右键物资图标可移除；存在库存或在途车辆时会先弹出确认框。
- 原版“存储”区域改为物资列表，每种物资都有独立库存显示和容量滑块。左键物资名称切换地图和半径滑块当前显示的物资。
- 每种已选物资使用独立库存槽和独立容量，单项最高 2000。
- 不论当前选了一种还是多种物资，搜集、配送和连接都走本 Mod。从多种减回一种时，会按剩下的物资重新连接。
- 范围内生产建筑凑满一整车后，会把已选物资送往还有空位的搜集中心。仅存储的物资不发车。
- 打开中心时地图一次只显示一种物资，默认是主物资。库存列表里左键物资名称可以切换，当前名称会高亮，半径滑块、数字和地面的圆一起换成这种物资自己的半径。拖动滑块只改变当前物资的覆盖范围。左键图标仍是仅存储，右键仍是移除。这种物资在自己的半径内且货车能到为绿色，半径内没路为红色，半径外但仍生产或消耗它为黄色。仅存储的物资不给建筑上色。鼠标放在建筑上会列出这座中心哪些物资经过它，以及能送到、没路、半径外还是仅存储。范围内货车到不了的建筑不会挂上配送中心，继续由公共供需配送。
- 某种产出被搜集中心覆盖时，仍优先留给还有一整车空位的搜集中心。范围内的搜集中心都装不下一整车时，这一车按公共需求送出。勾选了该物资的仓库即使已经挂在配送中心上，只要有路也会接收。
- 工厂配方的输入图标会列出来途数量和来源，并写明由哪座配送中心配送，或交给公共供需；旁边的配送图标使用同一说明。输出图标会列出在途去向，以及送往哪座搜集中心或交给公共供需。搜集中心箭头的说明改为优先搜集中心，其次全局处理。工业机器人和高科技工具的提示会显示在途货车，以及当前是暂不请求、由配送中心配送，还是交给公共供需。
- 配送中心只向货车能够到达的消费建筑配送已选物资。读档时只登记范围，进入游戏后再逐个确认道路；确认完成前这些建筑仍走公共供需。
- 已连接的搜集中心与配送中心会转运双方共同选择的物资。
- 物资选择随游戏存档保存。
- 配送按原版上报的需求分数排序，再结合库存缺口派车。
- 物流中心出口车辆会延后执行必要变道，减少出口附近交叉阻塞。

## 不属于本 Mod 的功能

车站轨道/道路端口方向、镜像和列车出生轨道已经拆到 `InfraSpaceStationTools`。

## 存档状态

以下数据由 `MultiResourceLogisticsMod` 随存档保存：

- 每个中心选择的物资名称；
- 每种物资的独立容量；
- 每种物资的覆盖半径；旧存档没有这项时，全部物资沿用中心原来的半径；
- 每种物资是否仅存储；旧存档没有这项时全部按正常搜集和配送处理；
- 为迁移旧存档暂时保留的车站端口字典。

旧车站字典只供 StationTools 一次性导入，不再驱动车站功能。

## 构建

项目默认引用：

`F:\SteamLibrary\steamapps\common\InfraSpace\InfraSpace_Data\Managed`

如果游戏安装位置不同，可通过 `GameManagedPath` 属性覆盖：

```powershell
dotnet build .\InfraSpaceMultiResourceLogistics.csproj -c Release -p:GameManagedPath="D:\Games\InfraSpace\InfraSpace_Data\Managed"
```

## 安装

把以下文件复制到：

`%USERPROFILE%\AppData\LocalLow\Dionic Software\InfraSpace\mods\InfraSpaceMultiResourceLogistics`

- `InfraSpaceMultiResourceLogistics.dll`
- `0Harmony.dll`
- `config.json`

进入游戏后，在模组列表启用该模组。

## 兼容性

- 兼容等级：C（需要 Mod 保持完整语义）。
- 卸载后存档可能仍能打开，但额外物资、容量和多物资调度会丢失或降级。
- 首次迁移请使用备份存档验证。

## 旧标识

程序集、配置名和根命名空间统一为 `InfraSpaceMultiResourceLogistics`。旧 `InfraSpaceMultiLogistics` 存档必须先使用仓库迁移工具生成副本。
