# 验证清单

## 自动验证

在仓库根目录执行：

```powershell
dotnet build .\InfraSpaceMods.sln -c Release
```

预期四个项目均成功，且无警告、无错误。

## 安装验证

退出 InfraSpace 后，分别执行四个项目目录中的 `Install.ps1`。确认：

- 脚本构建成功；
- DLL、`0Harmony.dll` 和 `config.json` 被复制到对应 Mod 目录；
- 游戏启动时四个 Mod 均被加载；
- 不遗留锁定 DLL 的 `.old` 文件。

## 游戏内回归

### Construction Tools

- 道路磁吸开关能即时生效，提示文字与实际状态一致；
- 框选移动、复制蓝图和取消操作正常；
- 复制物流中心时，多物资配置由物流 Mod 恢复；
- 复制车站时，端口配置由 Station Tools 恢复；
- 未安装另外两个 Mod 时，普通建筑复制仍正常；
- 移动或放置工厂时，黄色连线仍指向提高它产率的邻居，蓝色连线指向靠它提高产率的工厂，百分比与黄线一致；取消移动或放置后蓝线消失。未进入移动或放置时，单击已建成建筑不出现连线；按住鼠标左键约半秒后才显示黄线和蓝线，松开后消失。

### Production Insights

- 生产概览的筛选、排序和需求显示正常；列表末行合计等于当前可见行的就业、生产和消费，隐藏的全零行不计入，最终产物模式下消费合计跟随反推需求；就业显示为“总数/每座建筑”，工人标题的提示说明这个格式；勾选最终产物后，合计下方的效率行用工人列、生产列、消费列分别表示每件最终产物的人力、耗电和建筑，鼠标放在“效率”和三个数字上能看到换行说明、计入的建筑、分子、分母和算式；「最终产物」开关也有说明；选中地区后矿产、高科技工具和工业机器人排在前面，消费为 0 的最终产物排在最后，未选地区时恢复原顺序；选中地区后工业机器人和高科技工具仍显示产量和维护消耗；消费为 0 时产量为蓝色，鼠标放在蓝色数字上会说明它是最终产物；只有超出消耗的部分大于该地区产量最高的一座建筑时才为绿色，鼠标放在绿色数字上会列出产量、消费和多出的数量；资源图标底部的数字等于生产该资源的建筑数，未选区域时按全图、选中区域后只计该区域，末行图标处是这些数量之和；
- 单击生产概况中的资源图标后，生产该资源的建筑为绿色，其余场景变为白色总览；双击后需要该资源的建筑为蓝色；图标提示说明这两种操作；再点一次相同操作或改选其他可视化后恢复；选中区域时只标出该区域的建筑；
- 电力可视化中，不同电网的供电范围颜色不同，同一电网的范围同色；建筑颜色保持原版；
- 可视化面板下方列出全部工厂配方产物，没人生产的数量为 0；点选后生产该物品的建筑为绿色，其余建筑为灰色；再点一次或改选其他可视化后恢复；
- 大型存档打开面板时无明显卡顿或异常日志；
- 只读功能不改变模拟数据；但存档的 `scriptMods` 仍引用本 Mod，不能直接卸载后加载。

### Multi-Resource Logistics

- 集货中心和配送中心可配置多种资源、容量和车辆，每种物资容量最高 2000；只选一种，或从多种减回一种后，仍由本 Mod 把产出送往搜集中心、配送和重新连接；物资图标在没有配对中心或配对中心无路时标红，悬停可看到配对中心；左键图标变为灰色后该物资只存储，不再搜集、配送或转运，再点一次恢复，库存和容量保持；
- 搜集中心还能装下一整车时，范围内生产建筑的该物资不进入公共供需；都装不下时，这一车会派给其他有需求且道路可达的建筑，勾选了该物资的仓库即使挂在配送中心上也会接收；
- 工厂配方里，输入图标显示在途数量、来源，以及由配送中心还是公共供需配送，旁边的配送图标使用同一说明；输出图标显示去向和搜集中心；搜集中心箭头说明为优先搜集中心、其次全局处理；工业机器人和高科技工具的提示显示在途货车和当前配送来源；耐久降到一成时开始请求 1 个，到货后加成不断档；
- 保存、退出并重载后配置保持；
- 配送优先级、无路径处理和库存扣减符合预期；
- 打开搜集中心后地图默认只给主物资上色：范围内有路为绿色，范围外为黄色，范围内货车无法到达为红色；左键库存列表里的物资名称后，地图、半径滑块和地面的圆改成只显示该物资，其他物资的建筑不再变色；拖动半径只改变当前物资，切回去仍是上次保存的圆；仅存储的物资不给建筑上色；鼠标放在建筑上能看到这座中心每种相关物资是能送到、没路、半径外还是仅存储；配送中心按同样规则处理消费建筑；半径盖住但货车到不了的建筑及其旁边封闭产线仍由公共供需配送；反复点选中心时，已经确认过的颜色不来回跳；
- 禁用本 Mod 后，原版建筑仍存在，但多物资语义会降级。

### Station Tools

- 新建车站可切换道路口和铁路口方向；
- 列车生成方向选择符合配置；
- 保存、退出并重载后端口状态保持；
- 蓝图复制车站后端口配置被恢复。

## 旧存档迁移

使用包含旧 `AreaMove`、`RoadSnap`、`ProductionFilter` 和 `InfraSpaceMultiLogistics` 入口的存档：

1. 备份存档；
2. 用 `tools/migrate_save_identities.py` 生成新副本，禁止覆盖源文件；
3. 安装四个统一身份的新版 Mod；
4. 加载迁移副本并确认旧多物资中心配置仍在；
5. 确认 Station Tools 导入旧车站镜像、铁路口和道路口状态；
6. 保存到新槽位并完全退出游戏；
7. 重新启动并加载新槽位，确认状态仍在；
8. 查看日志，确认迁移没有反复覆盖新配置。

## 禁用与回退

- 四个入口类型都会写入 `scriptMods`，直接禁用任一 Mod 后加载对应存档可能反序列化失败；
- 需要卸载 Mod 时必须另做显式存档迁移，不能仅删除 DLL；
- 每次组合测试均使用存档副本，不覆盖唯一存档。
